# Career OS 使用与维护

Career OS 是现有 Jekyll 个人站的增量功能，入口为导航中的 **Career OS**，发布后地址为 `https://xu-zhy.github.io/career/`（若设置了 baseurl，链接会自动适配）。部署方式沿用当前 GitHub Pages；本次代码不需要新服务、密钥或数据库。

## 开始使用

1. 使用现代 Chrome、Edge、Firefox 或 Safari，通过 HTTPS 打开入口；本地可使用 localhost。浏览器需要支持 Web Crypto、Web Locks、dialog 和本地存储。
2. 首次设置至少 12 位的长口令，建议使用密码管理器生成并保存。数据默认空白，不把需求背景中的个人计划写进公开源码。
3. 在规划与任务中创建阶段、月度、每周和每日任务，可通过父级任务连接目标。删除父任务会解除直接子任务的关联。任务可按分类文本搜索、状态和日期筛选，日期按设备本地时区计算，本周从周一开始。
4. 在求职与面试中维护岗位、投递日期、下一步跟进和最终选择。岗位编辑窗口中的“添加一轮面试”可保存多轮面试日期、问题、回答、薄弱点与反馈。
5. 在技术知识库中维护分类、资料、核心总结、面试问题、关联项目和复习日期。资料作为纯文本保存，不执行 Markdown 或 HTML。
6. 表单点击“保存并加密”才会保存；保存成功后显示时间。未提交的编辑在锁定或离开页面后会丢弃。总览直接由三个模块汇总。

## 保密边界

- GitHub Pages 提供公开应用外壳，**并不提供服务端登录或私有页面**。页面可被访问，`noindex` 只是减少搜索收录，不是访问控制。
- 所有业务记录只保存在当前浏览器、当前站点来源的 localStorage，保存前通过 Web Crypto 使用 AES-256-GCM 加密。PBKDF2-SHA-256 使用 600,000 次迭代和随机 16 字节盐派生密钥，每次写入生成新的随机 12 字节 IV，并校验认证标签。密钥不可导出，口令和解密数据只在解锁期间驻留内存；锁定清理应用引用和表单，不承诺浏览器进程内存的物理擦除。
- 不向服务器发送记录，不提供明文导出，不加载第三方 JS、字体、统计或主页布局。独立 CSP 禁止网络连接、内联脚本、对象和表单提交；所有用户内容以 textContent / value 渲染。依赖标准原语并不等于经过独立密码学审计，Web Crypto 的使用要求参见 [MDN](https://developer.mozilla.org/en-US/docs/Web/API/Web_Crypto_API)。
- 离开或隐藏页面、手动锁定、刷新、闲置 5 分钟后，需要重新输入口令。多个标签页的修改通过 Web Locks 排队，并校验保存前的密文版本；另一页更新会锁定本页，避免静默覆盖。
- **无法抵御已解锁设备、恶意浏览器扩展、被篡改的站点代码或同源脚本攻击**。个人主页与工作台共用站点来源，其他同源页面可读取密文。口令强度决定离线猜测的难度；需要更强隔离时，应迁到独立域名并增加服务器认证。请保护 GitHub 账号、部署权限和使用设备。
- 口令无法找回。清理浏览器数据、隐私模式结束、更换浏览器、协议或域名都会导致无法直接访问原本机记录；隐私模式不适合长期保存。

## 备份与手机迁移

点击“导出加密备份”，得到 `career-os-日期.encrypted.json`。此文件仍需原口令解锁，不包含明文。通过可信渠道传到另一设备，打开同一页面，选择“从加密备份恢复”，提供文件及原口令，确认覆盖后恢复。恢复先校验格式、认证标签和数据结构，失败不修改现有记录。

恢复是**全量替换**，不做合并或自动云同步。先导出目标设备旧备份，再恢复；保留多个日期版本。两台设备分别修改后不要直接互相覆盖。仓库忽略 `*.encrypted.json` 仅为防误提交的辅助措施，请将实际备份存放在仓库外。

## 验证与部署

使用 Node.js 20+ 运行：

```sh
node --test tests/career.test.mjs
node --check assets/js/career/app.mjs
```

如果运行环境限制 Node 测试子进程，可直接执行 `node tests/career.test.mjs`，同样会运行全部断言。

本地完整站点按原项目方式执行 `bundle exec jekyll serve`，访问 `/career/`。源码包含 Jekyll front matter 与 `relative_url`，不应直接双击 HTML 文件进行验证。测试目录与辅助脚本已在 Jekyll 排除，`sitemap: false` 排除工作台页面。

提交并推送至当前 GitHub Pages 使用的发布分支后生效；代码改动不自动提交任何个人记录。上线后检查 HTTPS、创建空间、保存刷新解锁、备份恢复及手机布局。发布前请遵循仓库既有审查与发布流程。
